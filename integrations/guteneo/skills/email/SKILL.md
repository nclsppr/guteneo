# E-mail Guteneo

Utiliser le serveur MCP Guteneo connecté. Ne jamais demander une clé Resend, un mot de passe de document ou un secret d’authentification dans la conversation.

1. Appeler `get_capabilities` et lire la disponibilité réelle du canal e-mail, le mode simulation/production et les limites. Une fonction annoncée ne prouve ni sa disponibilité sur ce compte ni un mandat actif. Réutiliser les informations déjà fournies : destinataire, objet, message final et plafond. Ne pas inventer que le destinataire a demandé le message.
2. Choisir le mode demandé. **Sans fichier** : aucun `documentId`. **PDF joint** : réutiliser un PDF Guteneo `ready`, sans recréer l’original. **Lien protégé** : PDF `ready`, `options.emailDeliveryMode="protected_link"` et `options.protectedDays` parmi 1, 7 ou 30 (7 par défaut). Présenter le supplément d’hébergement indiqué par le devis, soit 1 € par document protégé lorsqu’il s’applique ; ne pas annoncer un prix d’envoi fixe inventé. Le destinataire reçoit un lien et saisit le mot de passe ; aucun compte destinataire n’est nécessaire dans ce parcours.
3. Pour le PDF uniquement, utiliser `get_document`/`list_documents`, ou `import_document` si l’hôte fournit réellement le fichier selon son contrat. Un chemin local n’est pas une URL distante. Sans transfert qualifié, proposer le dépôt dans [Documents Guteneo](https://guteneo.com/#/app/documents). Dans ChatGPT, ne pas importer de données sensibles exclues par la notice de l’outil. Suivre `analysis` : attendre le délai indiqué puis consulter le même document, au plus trois fois dans l’interaction ; ne pas réimporter et ne pas boucler sur les relances. Ne pas prétendre traiter Excel ou un autre format que le PDF.
4. Appeler directement `prepare_dispatch` avec `channel="email"`, `recipient.email`, `subject`, `text` et/ou `html`, l’éventuel `documentId`, les options choisies, le plafond et une clé d’idempotence stable. La préparation n’envoie rien. Présenter le message, le fichier ou son absence, le mode de remise, l’expiration éventuelle, le devis et le plafond. Suivre les `nextActions` retournées ; garder identifiants et empreintes dans les appels d’outils.
5. En mode standard, faire ouvrir `approvalUrl` pour la revue et l’approbation dans Guteneo, puis appeler `confirm_dispatch` après cette approbation enregistrée. Un oui dans le chat ne remplace pas l’approbation navigateur. Si un mandat expert actif couvre déjà cette connexion, le canal et le plafond, `review_dispatch` puis `approve_and_send_dispatch` peuvent être utilisés après lecture du message et de toutes les pages du PDF éventuel. Respecter la confirmation de l’hôte et l’attestation réelle `recipientRequested` ; ne jamais activer ou prolonger soi-même un mandat. Les comptes de revue limités à la préparation ne peuvent pas envoyer.
6. Pour un lien protégé, orienter l’expéditeur vers `emailDelivery.passwordAccessUrl`, dans son navigateur authentifié, pour consulter le mot de passe et le transmettre séparément au destinataire. Ne jamais ouvrir cette page avec un outil pour lire le mot de passe, demander qu’il soit copié ici, ni le joindre au même e-mail. L’assistant n’a aucun outil de lecture du mot de passe. La révocation se fait dans le compte Guteneo.
7. Suivre `get_dispatch_status` pour le même envoi. `accepted` signifie accepté par le prestataire ; `delivered` signifie remis au serveur destinataire, pas document ouvert. `submission_unknown` exige un rapprochement opérateur, sans nouvel envoi ni nouvelle clé. Ne pas réexpédier pour forcer un statut.

Les listes de destinataires multi-format, les pièces jointes Excel/autres fichiers et les comptes destinataires sont une évolution prévue, pas des fonctions à promettre ni à simuler. L’installation de ce plugin n’active aucun canal, aucun mandat ni aucune publication dans un annuaire.
