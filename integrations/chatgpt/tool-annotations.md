# Justification des annotations MCP — 21 septembre 2026

Revue statique des **24 outils** déclarés dans [mcp.ts](../../apps/api/src/mcp.ts), dans le candidat 0.2.2 basé sur `cffe58315e7646ea000d3ee09d87e045a98ce8c9`, avec les services postaux, la génération de page d’adresse, le transfert expert et la relance d’analyse raccordés comme dans [le point d’entrée API](../../apps/api/src/index.ts). Le nombre effectivement importé par **Scan Tools** doit être vérifié sur le serveur publié : cette table ne constitue pas une preuve de scan ou de qualification dans ChatGPT.

Les valeurs ci-dessous décrivent le code examiné. OpenAI demande des annotations correspondant aux effets réels, y compris ceux qui suivent une acceptation durable. Les confirmations de l’hôte ne remplacent ni les scopes, ni les droits de l’organisation, ni l’approbation Guteneo. Un compte fournisseur privé peut rester dans un périmètre fermé pour une simple lecture ; un hébergement externe ne suffit pas à rendre tout outil ouvert. Sources officielles consultées le 21 septembre : [annotations et élicitation](https://developers.openai.com/plugins/build/mcp-server#tool-annotations-and-elicitation), [règles des plugins](https://developers.openai.com/plugins/app-guidelines#correct-annotation), [soumission](https://developers.openai.com/plugins/deploy/submission).

## Correction locale à inclure dans le prochain snapshot

L’audit a relevé que `prepare_fax` annonçait `destructiveHint: false` alors que son paramètre `renewalOf` appelle `renewFaxQuote`, qui annule l’ancien envoi préparé dans la même transaction que la création du remplacement : [implémentation métier](../../packages/domain/src/index.ts), instruction `UPDATE dispatches SET status='cancelled'` dans `prepareDispatchInternal`.

**Correction locale du 21 septembre : `destructiveHint: true` pour l’outil entier**, puisque son annotation unique couvre également ce chemin. La description de `renewalOf` annonce désormais l’annulation définitive de l’ancienne commande préparée ; l’attendu du test des annotations est actualisé. Aucune logique métier de renouvellement n’a changé. Cette correction n’est pas encore une preuve de déploiement ou de scan dans le portail.

La PR #20 ajoute `create_postal_address_page`. Le candidat lui donne le titre « Créer une page d’adresse postale » et corrige `openWorldHint` à `false` : le [service](../../apps/api/src/postal-address-page.ts) lit l’original privé, consulte le seul profil Pingen configuré via `qualifiedProfile`, puis appelle le moteur privé de documents. Il ne transmet pas le PDF ou le destinataire à Pingen et ne contacte aucun domaine choisi par l’utilisateur. Cette portée est la même que celle de `get_postal_requirements` et `preflight_postal_pdf`. Les effets persistants de génération restent annoncés par `readOnlyHint: false` ; aucune logique métier n’a changé.

## Ajout au candidat 0.2.2

`get_postal_setup` est une lecture du compte connecté : annotations `(readOnly=true, destructive=false, idempotent=true, openWorld=false)`. `configure_postal_sender` enregistre l’expéditeur fourni par un administrateur OAuth ou requalifie explicitement la même configuration expirée : `(false, false, true, false)`. Il consulte uniquement le profil du compte Pingen configuré ; aucun document ni adresse d’expéditeur ne lui est transféré. Il ne remplace pas un expéditeur, ne restaure pas un arrêt, ne crée aucun mandat et ne déclenche aucun envoi. Une répétition identique réutilise la configuration ; cela ne promet pas des droits ou tarifs valides indéfiniment. Ce nouveau catalogue exige son propre scan dans ChatGPT.

## Précisions utiles pour la revue

- **Mandat expert :** `approve_and_send_dispatch` n’atteste jamais qu’un humain vient de relire le document. Il s’appuie sur le mandat borné et temporaire qu’un administrateur a activé au préalable dans le navigateur, pour ce client OAuth. Aucun outil ne peut l’activer ou le prolonger. Le transfert postal a sa propre autorité de transfert ; préparer le brouillon n’expédie pas le courrier.
- **Idempotence et issue inconnue :** `idempotentHint: true` décrit les effets métier d’un même appel ; il ne promet pas le même résultat après expiration des droits et n’autorise aucune nouvelle clé ni nouvel envoi en cas d’issue fournisseur inconnue. Les journaux et limites HTTP techniques ne sont pas des commandes d’envoi supplémentaires.
- **Annotations conditionnelles :** les fonctions générales et canaux annoncés ne prouvent ni un mandat actif, ni une route fournisseur autorisée. Les outils postaux, dont `create_postal_address_page` lorsque `generateAddressPage` est raccordé, et `rescan_document` sont enregistrés conditionnellement selon les services raccordés ; la configuration API complète examinée les raccorde tous.
- **Document postal dérivé :** la génération conserve la provenance et le destinataire, crée un PDF distinct avec une page d’adresse (et son verso blanc en duplex), puis applique les contrôles de document existants. Le transfert à Pingen, le devis et l’autorisation d’envoi restent des opérations séparées. Les informations publiques sur les documents créés, les destinataires, la conservation et les approbations restent applicables ; la génération n’ajoute aucun destinataire externe de données.
- **Portée de la preuve :** l’audit a lu les handlers, les services de documents/postal/expert et les opérations métier. Le test existant « exposes accurate action labels for every tool through the MCP transport » vérifie désormais les titres et annotations des 24 déclarations avec tous les services raccordés. Le test dédié à la page d’adresse vérifie également son titre, ses annotations et son scope. Une assertion copiée depuis les annotations ne prouve pas leur exactitude métier.
