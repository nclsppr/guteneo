À compléter
Pourquoi le contrôle à blanc reste une preuve partielle

Il relit l’état préparé, l’absence de tentative, le devis et les restrictions applicables. Il ne crée aucun devis, accord, crédit réservé, message en file ou appel fournisseur. Les échéances continuent de s’appliquer.

L’acceptation atomique et la livraison sont explicitement non exécutées. Les comptes et droits courants restent nécessaires. Les compteurs techniques d’accès peuvent évoluer ; une lecture réelle de production utilise aussi l’infrastructure.

Aucun test authentifié ni envoi réel n’est exécuté par cette page. La collecte publique est distincte des tests métier.

Stratégie de tests sans débit métier
  1. Exécuter localement le code applicatif avec des données fictives, des bases D1 et objets R2 isolés, les files et les composants PDF requis.
  2. Interdire le réseau externe et exclure les secrets de production. Le dernier appel de livraison utilise exclusivement un fournisseur simulé ; tout accès réseau inattendu fait échouer le test.
  3. Conserver les preuves par scénario : environnement, résultat, date, durée et limite. Un scénario non exécuté ne reçoit aucun état vert.
  4. Conserver la production hors de cette boucle. La collecte publique est limitée et utilise l’infrastructure ; son coût ne peut pas être présenté comme nul. Aucun parcours métier facturable ne doit être inclus dans cette boucle.

Objectif : aucun devis réel consommé, aucun crédit métier réservé et aucun paiement fournisseur. Les ressources de la machine et d’une éventuelle CI restent distinctes. La qualification locale publie son résultat daté dans Vérifications. Les scénarios non couverts restent à compléter.
