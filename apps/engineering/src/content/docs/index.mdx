guteneo turns exact documents into reviewable communications. A browser, native
client or connected assistant can prepare work; the server decides which actor
may read it, approve its immutable version and request delivery. PDF verification,
provider readiness, budgets and delivery evidence remain separate checks.

This site explains the implementation and the decisions behind it. It serves
engineers and integrators; customer task guides belong to the separate future
customer documentation site.

## The commitments that shape the code

**Preserve the original.** Uploaded PDF bytes have a stable hash. Rendering,
address-page creation and Studio generation produce distinct document versions;
they do not silently modify an approved original.

**Keep permission and approval distinct.** Workspace membership and OAuth scopes
control access. Approval binds exact content, recipient, options and cost. An
assistant connection is not human consent; optional delegation is a separate,
bounded administrator decision.

**Commit before dispatching.** Acceptance, quota reservation and outbox insertion
are atomic. Queue publication can repeat; a conditional claim controls provider
attempts. An unknown provider outcome requires reconciliation rather than blind
retry.

**Describe the evidence.** Implemented code, an enabled account capability, a
local fixture, a deployed release and a verified delivery prove different things.
Feature pages retain that distinction. They are an engineering inventory, not a
promise that every account, host or country is currently enabled.
