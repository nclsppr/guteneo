# Guteneo engineering documentation

Repository-wide [engineering rules](../../AGENTS.md) apply. This app extends the
approved [Guteneo visual identity](../../docs/BRAND_IDENTITY.md); the content and
publication contract lives in [ENGINEERING_SITE.md](../../docs/ENGINEERING_SITE.md).

## Ownership and authoring

- `src/content/docs/` contains the curated English MDX pages. Frontmatter requires
  `title`; supply a concise `description`. The layout renders the H1, so body
  sections start at H2. Set `sidebar.label` and `sidebar.order` for navigation.
- `src/content/docs/features/` is generated by the root engineering-content
  script. Change its sources, regenerate, and check; do not edit generated pages.
- `src/components.ts` registers shared MDX components. Prefer an existing
  component or a partial under `src/content/partials/` to repeated guidance.
- `src/styles/globals.css` owns tokens; `engineering.css` owns branded layout
  refinements. Preserve native Nimbus search, sidebar, TOC and page actions.
- Keep `AgentDirective` and `WebMCP` in `BaseLayout.astro`, and
  `data-pagefind-body` on the docs content. Preserve Markdown/source twins,
  `/llms.txt`, `/llms-full.txt` and agent discovery routes.

## Local commands

Run from `apps/engineering` after `npm ci`:

- `npm run dev` regenerates the feature reference before starting Astro.
- `npm run typecheck` checks the Astro app independently of root TypeScript.
- `npm run build` verifies generated content, renders static pages and builds
  Pagefind search. Search works after this build; use `npm run preview` to test it.
- `npm run lint:docs` checks authoring and internal links against the built route
  manifest. Run it after the build.
- `npm run check -- --json` reports Nimbus structural and agent-surface checks.

Static Cloudflare configuration is in `wrangler.jsonc`. Package deployment goes
through the repository's dedicated guard; repository authorization rules apply.

## Nimbus maintenance

This site was scaffolded with the official Cloudflare CLI. Pin package versions
and keep `nimbus.json` committed; it records the reviewed upgrade baseline.
Consult the installed, release-matched
[`docs-for-agents.md`](node_modules/@cloudflare/nimbus-docs/dist/docs-for-agents.md)
and [official documentation](https://nimbus-docs.com/) for package APIs.

Before upgrading, inspect `nimbus-docs outdated` and
`nimbus-docs migrate --dry-run --diff`; review changes before applying them.
Registry UI installs use `nimbus-docs add <slug>`. Do not remove customized files
or reset unrelated work to apply an upstream starter update.
