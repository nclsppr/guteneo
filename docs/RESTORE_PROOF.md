# Local backup and restoration rehearsal

Executed by `npx vitest run tests/integration/restore.test.ts` on 16 September 2026. The test passed in 3.64 seconds in the first isolated run. Machine-readable evidence is regenerated at `reports/restore-proof.json`; the current full-suite JSON report may include a later repeat.

## What actually ran

- Two independent Cloudflare Miniflare runtimes, each with its own D1 and R2 binding; all current versioned migrations applied to both. The machine-readable proof records the resulting table and row counts.
- A real one-page PDF generated by `pdf-lib`, stored in private local R2 and registered with its SHA-256.
- A fictional postal preparation, browser approval, atomic credit reservation/outbox, publication and one simulated provider call. Its result was intentionally uncertain with a known simulated remote resource ID.
- Producers and consumers quiesced for a logical D1 snapshot. Application tables, rows and foreign-key dependencies were read; the R2 object's exact bytes were copied separately.
- All rows restored into the fresh database in dependency order, with business triggers temporarily absent only in the isolated restore target, then recreated from the migrated schema. This avoids replaying business side effects while restoring facts. A foreign-key check returned zero violations.
- The R2 bytes restored and SHA-256 compared with the original; the restored PDF was parsed and had one page.
- Duplicate processing and lease reconciliation attempted after restoration. The command stayed `submission_unknown`, its remote ID and reserved credit were retained, and **zero new provider calls** occurred. The outbox remained published.
- A simulated authenticated provider fact reconciled the known resource to `handed_to_post`, confirmed its reserved credit, and still caused no new send. The result is explicitly simulated: no physical letter was posted.

## Meaning and limits

This verifies that the implemented command state, quota reservation, outbox and document identity survive a quiesced local restoration, and that replaying an uncertain restored command cannot automatically submit it again. It also exercises current migration/schema compatibility on a clean target.

It **does not** prove a hosted Cloudflare export, an online transactionally consistent snapshot, independently hosted/encrypted backup retention, provider reconciliation with a real account, production recovery time, production recovery point or geographical redundancy. The timing is a small local test duration, not an RTO promise.

A production restore must pause consumers and publication, use the supported consistent D1 backup/export mechanism, restore matching private R2 content, validate every retained object hash, and reconcile pending/submitting/unknown commands with provider facts before releasing any consumer. A database snapshot can predate a physical send: restored `queued` alone is never proof that the provider did not receive it after that snapshot. The rehearsal deliberately does not authorize replay of such commands.

The test-generated PDF and recipient are fictional fixtures. No account, recipient, key, number or postal destination was used in a real connector call.
