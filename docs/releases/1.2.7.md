# Guteneo 1.2.7 — Gare and the reviewed SQL publication transport

This candidate includes the separate Gare station experience and the publication
checks prepared in the unpublished 1.2.5 and 1.2.6 candidates. Gare keeps its own
static client at the intended origin `https://gare.guteneo.com`, using the existing
Guteneo account and canonical API.

## The Gare experience

- Eleven destinations, including a public hall, organize dispatches, preparation,
  documents, personal arrivals, secure distributions, recipients, schedules,
  templates, usage and account navigation.
- French, English, German and Luxembourgish interfaces support day and night
  themes, narrow screens and reduced motion.
- Eligible plain-text email has an exact native review, explicit content consent
  and the required recipient-request attestation. Existing approval, cost and
  confirmation rules still apply. Specialist editing and more complex review
  continue through clearly identified canonical Guteneo interfaces.
- Session and workspace changes invalidate old requests and private views.
  Cross-origin access is limited to the configured same-site station origin;
  existing host-only cookies, CSRF and server authorization remain in force.

## Publication transport correction

The local operator passes reviewed SQL as an explicitly bound `--command` value.
A migration beginning with an SQL comment must remain data, even though its first
characters resemble a command-line option. This preserves the complete SQL batch
and its migration-ledger statement without rewriting the migration or changing
the existing transactional transport.

The preceding attempt was rejected during command-line parsing. Independent
hosted ledger inspection confirmed no migration advancement. The correction does
not retry unknown mutation outcomes or add a migration, permission, provider
activation or sending authority. Exact main, successful CI, the version tag,
scoped identity and schema/integrity checks remain publication prerequisites.

## Validation and release scope

Regression checks cover the command-line argument boundary, alongside the
existing reviewed-migration and publication guards. Browser recovery checks wait
for the replacement document before inspecting an explicit reload, preserving
their navigation, recovery and no-write assertions. Integration manifests and
archives are rebuilt and validated at the synchronized version 1.2.7. Existing
MCP tools, schemas, scopes, instructions and consent requirements are unchanged.

The preceding candidate passed complete PR CI, including all 150 Gare desktop
and mobile cases; main qualification verified reuse of that identical tree.
This candidate still requires its own exact-source CI and independent served-byte
verification. Synthetic tests and local simulation do not establish production
Auth0 return, provider delivery, billing or a real communication.
