# Guteneo 1.2.6 — Reliable operator publication checks

This candidate includes the unpublished [Gare experience from 1.2.5](https://github.com/nclsppr/guteneo/blob/main/docs/releases/1.2.5.md).
The station interface, customer journeys and business permissions are unchanged.

## What changes

The authorized local publication runner gives CI qualification and concurrent
publisher discovery separate bounded API-read budgets. Previously, these two
independent phases shared one minute: network latency could exhaust that budget
before any database or application change. Both phases retain their complete
checks, and publication still requires clean exact main, its successful CI and
version tag, the reviewed schema and the existing scoped Cloudflare identity.

The operator instructions also preserve the existing GitHub CLI configuration
explicitly when a separate encrypted Wrangler profile uses `XDG_CONFIG_HOME`.
This avoids hiding GitHub's established login without copying credentials or
granting additional access.

## Validation and release scope

Focused regression checks cover the independent bounded readers. The preceding
1.2.5 main revision passed complete hosted CI, including all 150 Gare desktop and
mobile cases; that result does not replace exact-source qualification of this
candidate. The new revision must pass its own release gates before publication.

The earlier operator attempts stopped before any migration or publication.
This candidate does not change the reviewed migrations, retry unknown mutation
outcomes, activate providers or send a real communication. Production availability,
served bytes and authenticated browser behavior remain separate verification.

Application and portable/Claude/Cursor package versions advance together to
1.2.6, with refreshed metadata and a rebuilt integration archive. Existing MCP
tools, schemas, scopes, instructions and consent requirements remain unchanged.
