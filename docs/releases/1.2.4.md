# Guteneo 1.2.4 — Quieter decisions and exact counts

This update follows the unpublished 1.2.3 candidate and includes all of its
changes ([1.2.3 notes](1.2.3.md)). It corrects defects found by comparing the
recovered clarity plan with current main. It also completes the remaining audit
items without changing prices, authority or recovery choices.

## What changes

- An approval request is visible only in the browser. Assistants and the native
  application no longer receive the requester on a dispatch. In Overview, the
  attention queue flags a dispatch whose current version a preparer asked to
  have approved. Its rows show the channel instead of raw identifiers.
- Document lists no longer draw a first-page thumbnail in the browser. Drawing
  one read the protected file and recorded a document view that nobody had
  made. Studio template thumbnails are unchanged.
- A table row still opens with a pointer click, but its text can now be
  selected and copied. Controls inside the row keep their own action.
- Browser validation now uses the product language. It covers fax numbers,
  email addresses and spending limits. A folded spending limit opens by itself
  when its value is invalid instead of blocking the form silently. The fax and
  email limit is folded like the postal one, with the current amount in its
  summary.
- Administration keeps its banner for delayed transmission only. The amber
  "Needing attention" figure opens the matching activity list. A breakdown with
  a single category shows its figure without a full-width bar.
- Belvédère counts use complete singular and plural messages in all four
  languages. A missing net profit reads as a sentence, not a headline figure.
- Unknown dispatch events read in sentence case. The account page and the
  workspace invitation carry their own lowercase tab titles.
- The preview accessibility suite now fails on serious violations as well as
  critical ones.

## Validation and release scope

Local verification results and their environment are recorded in the pull
request that carries this candidate. They do not replace a complete successful
hosted CI run on the exact source to be released.

This candidate adds no migration. The plugin and MCP contract move to 1.2.4
because a dispatch read no longer includes the browser approval request. That
change was made in the shared domain service, which the integrations import.
Manual production publication keeps the requirements described for 1.2.3.

Saved recipients, signed customer webhooks, capped future schedules and durable
iOS drafts from main remain unchanged. This release does not activate disabled
tenant or provider gates, enable expert delegation, send real communications or
establish a native distribution result.
