# Administration and Belvédère clarity candidate

Dated 10 November 2026. This implements remaining presentation work from the
9 November page audits on the rebased Claude branch. This is local candidate
source; no deployment, provider activation, communication or hosted proof is
claimed.

## Administration

Report pages put period presets and refresh beside the title. Custom UTC dates
remain a disclosure that opens for an explicit custom period or a validation
error. All URL filters, Back recovery, maximum duration, authority rechecks and
aborted late exports retain the existing
[Administration contract](WORKSPACE_ADMINISTRATION.md).

Primary and secondary figures share grid tracks. A period shorter than three
days omits the daily chart; one service uses a named amount instead of a
single-bar comparison. The underlying totals and report data are retained.
Activity starts with reference, date, channel, state and consumption. A Columns
disclosure reveals pages, destination country, reservation and approver from the
same authorized rows, without a request or persisted personal values.

Reports use one list with one format selector and one explicit download per
row. Format restrictions, export audit, privacy notice, row limits, preview
refusal and late-download cancellation remain intact. The billing profile's
existing status, consequences and available action share one responsive row;
no billing command or consent changes.

Audit rows use a fixed description allowlist. Human approval and delegated
approval are named separately. Unknown actions receive a neutral label; the
original action code remains available in Details. No audit detail payload,
recipient or document content is added to the response or displayed.

The Members heading links to the existing roles guide. Settings contains only
workspace identity. Operational controls now have the canonical
`/app/administration/operations` page. Administrators retain their current
rights; supervisors with report permission, operators and observers receive
the role notice before operational reads. OAuth/MCP/native APIs and all
server mutation gates remain unchanged. Opening Settings no longer starts
`GET /api/admin` or the attention dispatch read; opening Operations does.

## Belvédère

List counters and pagination use complete singular/plural messages in all four
languages. Dispatch/workshop lists show one main value per financial cell;
transport, hosting, quote and cap breakdowns remain available in Details.
Additional authorized fields are not fetched. Missing verified receipts show a
dash with an accessible configured-state label and the existing explanation;
unknown is never presented as zero. Financial consumption, receipts, verified
provider costs, promotional credits and unavailable accounting profit retain
their separate meanings.

On phones, Filters opens the period and data selectors. The selected production
or simulation evidence label remains visible when filters are collapsed.
Custom dates open the relevant controls; resizing restores desktop controls.
The platform read authority, separate query paths and selected-language lazy
modules remain unchanged.

## Evidence and limits

The candidate adds unit coverage for audit label privacy and human/delegated
approval distinction, and full count messages in four languages. Browser
regressions cover optional columns without a new read, collapsed diagnostic
codes, one format selection/download, deferred operational reads and direct
Operations refusal for all three non-administrator roles. Existing Belvédère
browser expectations now open mobile filters and preserve receipt uncertainty.
Execution results belong to the final branch verification record; adding these
cases does not claim that they have run.

No measured loading-time improvement is asserted. The request boundary is
explicit and covered by the browser regressions; root bundle/network timing
requires the final source build and environment record.
